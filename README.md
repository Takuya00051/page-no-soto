# 頁の外（PAGE NO SOTO）

小説の登場スポットを地図で巡る、閲覧専用のサイト。京都中心、ときどき京都の外へ。
静的サイト（Leaflet + OpenStreetMap、APIキー不要）で、データは `data.json` 一つに入っています。

公開URL: https://takuya00051.github.io/page-no-soto/

## 使い方（閲覧）

- サイドバーで作品にチェックを入れると、その作品の登場スポットにピンが立つ
- ピンをクリックすると、その場所で小説の中で何が起きたかが表示される
- 複数作品にチェックを入れると、共有されている場所のピンが作品色の扇形になる
- 選択状態は URL のハッシュ（例 `#yoru-mijika,yojohan`）に反映されるので、その状態のまま共有できる
- サイドバー上部の「場所で探す」に地名を入力すると、地図がそこへ移動し、その場所が登場する作品に自動でチェックが入る。登録済みの場所に一致しない場合は外部の地名検索（🌐 表示）にフォールバックし、未登録の場所でも地図上で見つけて仮ピンを表示できる。その仮ピンのポップアップから「このままピンを追加」を押せば、座標入力済みで「新しい場所を追加」フォームが開く
- 「作品を選ぶ」の検索欄で作品名・著者名を検索でき、並び替え（著者名・作品名・刊行年）もできる。既定は「著者名（折りたたみ）」で、著者ごとにグループ化され、既定では閉じた状態で表示される。刊行年ソートも同様にグループ化・折りたたみ表示になる
- 著者名は漢字のままだと五十音順にならないため、「著者フリガナ」を入力しておくとそちらでソートされる（未入力の場合は著者名の文字列でソート）
- 著者名・刊行年のグループを開くと、一番上に「すべて選択する」（すでに全部選択済みなら「すべて解除する」）が出て、そのグループの作品をまとめてチェックできる
- 「作品を追加」の著者欄は、登録済みの著者名がサジェストされる（ブラウザ標準の入力補完）
- 作品の ⓘ ボタンから詳細画面を開くと、表紙・あらすじ（自動取得 or 手入力）・登場する場所の一覧を見られる

## データの更新方法①: サイト上で編集（推奨）

地図左下の「ピンを追加」「作品を追加」ボタンから、フォームでシーン・場所・作品を追加編集できます。

- 作品・場所はプルダウンから選択。「＋ 新しい〜」を選ぶと入力欄が出る
- 新しい場所は「地名・住所で検索」欄に入力すると候補が出て、選ぶと座標が自動入力・地図もそこへ移動する（OpenStreetMap Nominatim）。地図を直接クリックしても座標を入力できる
- 地図左下の「作品を追加」から、ピンなしで作品情報だけ先に登録できる（あとから「ピンを追加」でシーンを追加）
- 編集パネルを開いていない状態でも、地図の何もない場所をクリックすると「ここにピンを追加」のポップアップが出て、そこから登録フォームを開ける
- 新しく置いた仮ピン（新規登録・位置打ち直し・地名検索結果）は、カーソルを乗せる（タッチ端末はタップ）と小さな×が出て、押すと取り消せる
- 既存の作品×場所の組み合わせを選ぶと本文が読み込まれ、更新・削除ができる
- 既存の場所を選ぶと「ピンの位置を打ち直す」で座標を修正できる（地図クリック→この位置で保存）
- 「作品情報を編集」を開くと、既存作品のタイトル・著者・刊行年・色・ISBN・表紙URL・あらすじを後から修正でき、「この作品ごと削除」もできる
- 「下書き」にチェックすると、その作品はトークンを設定したブラウザ（＝自分）にだけ「下書き」バッジ付きで表示され、他の閲覧者には出ない（※ data.json 自体は公開リポジトリにあるので、完全な秘匿ではない点だけ注意）
- 京都以外（奈良・滋賀・大阪・東京など）のスポットも登録可能。初期表示は京都のまま。サイドバー下、または地図右下の🎯ボタンの「表示中のピンに画面を合わせる」で選択中の作品のピン全体へ移動できる

### 写真から入力（OCR + 場所候補の自動提案）

編集パネル上部の「📷 写真から入力」で、読んでいる本の該当ページを撮影・選択すると:

1. 写真の文字を読み取り（Tesseract.js、初回のみライブラリを読み込むため数秒かかる）、「該当箇所の文章（引用）」欄に自動入力する
2. 読み取ったテキストの中から、登録済みの場所や、よく知られた京都周辺の地名候補（✨、`landmarks.js` に一覧）を見つけて候補チップとして表示する
3. 候補をクリックすると、既存の場所ならそのまま選択、未登録の地名なら「新しい場所」フォームが開き、名前を入れたうえで座標も自動検索（OpenStreetMap Nominatim）される

OCRの精度は写真の状態や縦書き・字体によって変わるため、読み取り結果や座標は保存前に必ず確認・修正してください。手動での登録（地図クリック・プルダウン選択）は今まで通りいつでも使えます。

保存先は2通り:

1. **GitHub トークンを設定した場合（推奨）**: 保存すると `data.json` が GitHub に直接コミットされ、1分ほどでサイトに反映される。
   - トークンの作り方: GitHub → Settings → Developer settings → **Fine-grained personal access tokens** → Generate new token。対象リポジトリを `page-no-soto` のみに絞り、Repository permissions の **Contents: Read and write** だけを付与する
   - 編集パネル内「保存先の設定」にトークンを貼って保存（このブラウザの localStorage にのみ保存される。共用PCでは設定しないこと）
2. **トークン未設定の場合**: `data.json` がダウンロードされるので、リポジトリの `data.json` と差し替えて push する

閲覧者にも編集ボタンは見えますが、トークンがなければリポジトリには何も書き込めません。

## データの更新方法②: data.json を直接編集

`data.json` は次の構造です。

```json
{
  "spots": {
    "tetsugaku-no-michi": {
      "name": "哲学の道",
      "kana": "てつがくのみち",
      "lat": 35.0271,
      "lng": 135.7944,
      "note": "銀閣寺から南禅寺へ続く散歩道。"
    }
  },
  "works": [
    {
      "id": "sabaku",
      "title": "作品名",
      "author": "著者名",
      "color": "#7a5ca8",
      "scenes": [
        {
          "spot": "tetsugaku-no-michi",
          "text": "この場所で何が起きたかを書く。",
          "quote": "該当箇所の短い引用（省略可）"
        }
      ]
    }
  ]
}
```

- 場所は `spots` で一元管理し、作品の `scenes` から ID で参照する。複数の作品が同じ `spot` を参照すると自動的に扇形ピンになる
- 作品や場所を丸ごと削除・改名したいときはこちらの方法で
- 緯度・経度は Google マップで右クリックすると表示される数値をコピーすればよい
- `quote` は本文からの引用。公開サイトなので、引用は短い範囲にとどめること（出典は作品名として表示される）

## スポット写真・作品の表紙とあらすじについて

- ポップアップの写真は、`spots` の該当エントリに `"photo": "画像URL"` を手入力した場所だけ表示されます（未入力の場所は「🔍 写真を検索」のタイルが出るだけ）。座標検索での自動取得は、的外れな写真が出やすかったため廃止しました。
- 作品詳細の表紙・あらすじは、`works` の `cover`（画像URL）・`synopsis`（あらすじ本文）を手入力していればそれを優先表示します。未入力の場合は Google Books API でベストエフォート取得を試みますが、無料の匿名アクセスのため取得できないことがあります（その場合は「見つかりませんでした」と表示され、致命的な失敗にはなりません）。確実に表示したい場合は編集画面から手入力してください。
- `isbn` は表紙・あらすじの自動取得には使っていませんが、書誌情報として保持しています。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | ページ本体 |
| `data.json` | **作品・場所データ** |
| `landmarks.js` | 写真OCR機能が使う、未登録の有名地名候補リスト |
| `app.js` | 地図・ピン・ポップアップ・場所検索・作品詳細の表示ロジック |
| `editor.js` | サイト上の編集機能（GitHub コミット／ダウンロード／写真OCR） |
| `style.css` | デザイン |

公開ページは同一オリジンの `data.json`（GitHub Pages のデプロイ結果）だけを読みます。`raw.githubusercontent.com` 経由の直接取得は、コミット直後でもエッジキャッシュの反映タイミングがばらつき、更新が反映されないことがあったため使っていません。編集を保存すると GitHub Pages が自動でデプロイし直すので、**保存後1分ほど待ってからリロード**すれば反映されます（デプロイ状況は [Actions タブ](https://github.com/Takuya00051/page-no-soto/actions) で確認できます）。

このリポジトリは `page-no-soto` 専用です（以前 `ClaudecodeTest2/kyoto-literary-map/` にあったものをここへ移行しました）。GitHub Pages の設定は Settings → Pages → Source: **Deploy from a branch** / `main` / `/ (root)`。

`app.js` / `editor.js` / `style.css` / `landmarks.js` はブラウザに10分キャッシュされる（GitHub Pagesの既定）。`index.html` の `<script src="app.js?v=2">` のように付けている `?v=N` がキャッシュ回避の目印なので、**これらのファイルを更新するたびに `index.html` 内の該当する `?v=N` を1つずつ増やす**こと（data.json自体は別途 `?t=タイムスタンプ` で常にキャッシュ回避しているので対象外）。
